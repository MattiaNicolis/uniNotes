\chapter{Procedure}
L'uso delle procedure permette l'\textbf{astrazione del controllo}.

\vario{Nota}{
    Astrarre significa nascondere dettagli facendo emergere caratteristcihe comuni.
}

L'astrazione chiede di identificare le proposizioni importanti che si vuole descrivere al fine di concentrarsi che si vuole descrivere al fine di concentrarsi sulle questioni rilvanti e ignorare quelle non importanti.

\smallskip
Quando si parla di astrazione del controlllo ci sono, in realtà, due categorie di sottoprogrammi con nome nome che possiamo definire:
\begin{itemize}[label=$\diamond$, itemsep=\smallskipamount]
    \item \textbf{procedure} (no output)
    \item \textbf{funzioni} (restituisce output)
\end{itemize}

\smallskip
Partre importante del processo di astrazione consiste nel dare al raggruppamento un nome.\\[0.2ex]
Il \textbf{nome} permette di rifersi all'astrazione senza conoscerne i dettagli, una solo le caratteristiche di interesse che ne hanno determinato il raggruppamento.\\[0.2ex]
I \textbf{parametri} permettono l'astrazione di tante computazioni simili che cambiano di tante computazioni simili che cambiano solo per alcuni input a cui vengono applicate e che vengono abbreviate con un singolo nome.\\[0.2ex]
Il \textbf{corpo} è ciò che viene valutato/eleborato/eseguito ogni volta che il nome viene richiamato.

\smallskip
Una procedura viene definita in tre fasi:
\begin{enumerate}[itemsep=\smallskipamount]
    \item \textbf{specifica}: descrizione dell'interfaccia della procedura/funzione
    \begin{lstlisting}[language=C]
        double P(int x) {
            
        }
    \end{lstlisting}
    \item \textbf{definizione}: descrizione del copro della procedura/funzione
    \begin{lstlisting}[language=C]
        {
            double y;
            //corpo procedura P
            ...
            (return y);
        }
    \end{lstlisting}
    \item \textbf{uso}: chiamata della procedura/funzione per eseguire il codice
    \begin{lstlisting}[language=C]
        int n;
        double z;
        z = P(n); //chiamata della procedura
    \end{lstlisting}
\end{enumerate}

Consideriamo il seguente codice:
\begin{lstlisting}[language=C, caption=programma di esempio]
    int foo(int n) {
        int tmp = a;

        if(tmp == 0)
            return n;
        else
            return n + 1;
    }
\end{lstlisting}

In questo caso la variabile \texttt{a} è un identificatore non locale, cioè un identificatore libero per cui di deve trovare il significato nel contesto.\\[0.2ex]
Il problema è che nel contesto del chiamante potrebbero esserci più definizioni di \texttt{a} e non è chiaro quale sia quella a cui si riferisce la procedura.\\[0.2ex]
Di conseguenza, la regola di visibilità delle dichiarazioni non è più sufficiente per risolvere i riferimenti quando si usano le procedure se la procedura ha un ambiente non locale.

\begin{mydef}{Ambiente di una procedura}
    L'\textbf{ambiente di riferimento} di una procedura è l'insieme di tutti i nomi che sono visibili al comando.
\end{mydef}

L'ambiente di riferimento di una procedura è determinato da vaire tipologie di regole:
\begin{itemize}[label=$\diamond$, itemsep=\smallskipamount]
    \item \textbf{regole di scope} (statico o dinamico)
    \item \textbf{regole di visibilità}: determinano quali dichiarazioni sono visibili in un certo punto del programma
    \item \textbf{regole di binding} (shallow o deep): determinano a quale dichiarazione si riferisce un certo identificatore
\end{itemize}

\section{Regole di scope}
Le regole di scoper possono essere distinte in due tipologie:
\begin{itemize}[label=$\triangleright$, itemsep=\smallskipamount]
    \item \textbf{scoper statico}: prevale il contesto di definizione.
    
    L'ambiente di riferimento è quello attivo al momento della definizione della procedura.
    \item \textbf{scope dinamico}: prevale il contesto di esecuzione.
    
    L'ambiente di riferimento è quello attivo al momento della chiamata della procedeura.
\end{itemize}

Con lo scope statico il riferimento per \texttt{x} è \texttt{P}. ovvero si risale la catena di annidamento dei blocchi (\textbf{catena statica}), nota a tempo di compilazione.

\begin{figure}[H]
    \centering

    \caption{catena di definizione}
\end{figure}

\begin{lstlisting}[language=C, caption={codice esempio con scope statico}]
    {
        int x = 0;

        void pippo(int n) {
            x = n + 1;
        }

        pippo(3);
        write(x); //stampa in ogni caso 4

        {
            int x = 0;
            pippo(3);
            write(x);
            //stampa 0 perche' pippo(3) va a modifica il primo valore
            //di x, ma la write si riferisce all'ultima istanza (x = 0)
        }

        write(x); //stampa in ogni caso 4
    }
\end{lstlisting}

\section{Visibilità delle dichiarazioni}
Una dichiarazione può essere visibile:
\begin{itemize}[label=$\triangleright$, itemsep=\medskipamount]
    \item \textbf{a partire dalla dichiarazione e fino alla fine del blocco}
    \begin{lstlisting}[language=C]
        {
            a := ...
            .
            .
            .
            int i := int //visibile da qui in giu'
        }
    \end{lstlisting}
    \item \textbf{all'interno del blocco visibile sempre}
\end{itemize}

\section{Implementazione dello scoping statico}
Si basa sulla concetrazione della \textcolor{colore}{\textbf{catena statica}}, ovvero sulla determinazione dei \textbf{link statici} (puntatore all'RdA che immediatamente contiene il testo del blocco in esecuzione).

\begin{mydef}{Profondità statica (Sd)}
    La profondità statica di un blocco A è la profondità di annidamento di B.
\end{mydef}

La profondità statica è un'informazione che si può estrarre a tempo di compilazione.

\vario{Notazione}{
    $\mathrm{Ch} \to $ funzione chiamante
}

Quando $\mathrm{Ch}$ chiama una procedura $\mathrm{P}$, $\mathrm{Ch}$ sa se la definizione di $\mathrm{P}$:
\begin{itemize}[label=$\diamond$, itemsep=\smallskipamount]
    \item è immediatamente contenuto in $\mathrm{Ch}$ ($\mathrm{k = 0}$)
    \item è contenuto in un blocco che si trova $\mathrm{k}$ passi di annidamenti statici fuori da $\mathrm{Ch}$
\end{itemize}

\[
    \mathbf{k = Sd(Ch) - Sd(P) + 1}
\]

dove:
\begin{itemize}[label=$\triangleright$, itemsep=\smallskipamount]
    \item $\mathbf{k = 0}$: $\mathrm{Ch}$ passa a $\mathrm{P}$ il suo indirizzo il link statico
    \item $\mathbf{k > 0}$: $\mathrm{Ch}$ risale di $\mathrm{k}$ passi la catena statica e restituisce l'indirizzo dell'RdA raggiunto come link statico
\end{itemize}
